# Hanzi Cards — offline Chinese → English

Рабочий исходный комплект мобильного MVP для iOS/Android. Интерфейс и комментарии
в коде — английские. Это не копия Anki, Pleco или HelloChinese; их названия
описывают ожидаемые сценарии. В комплекте шесть авторских слов, а не полный HSK.
Все файлы реализации приведены целиком, без заглушек.

## 1. Стек и архитектура

React Native + TypeScript, Expo, expo-sqlite, expo-speech, react-native-svg,
react-native-safe-area-context. Бэкенд и учетная запись не нужны.
SQLite сохраняет карточки и историю локально между запусками.
Чистые функции расписания и проверки письма отделены от UI и БД.

Используется официальный blank-typescript шаблон: он подбирает совместимые
версии React/React Native/Expo. Скрипт устанавливает нативные модули через
expo install. После установки сохраните package.json и package-lock.json:
в дальнейшем воспроизводимые установки выполняются через npm ci.

```text
hanzi-cards/
├── App.tsx                         # Queue, filters, writing screen
├── src/
│   ├── db.ts                       # SQL schema, seed, atomic reviews
│   ├── srs.ts                      # Four-grade SM-2 adaptation
│   ├── speech.ts                   # System TTS, cancellation, errors
│   ├── strokes.ts                  # Ordered trajectory comparison
│   ├── components/
│   │   ├── Flashcard.tsx
│   │   └── WritingCanvas.tsx
│   └── data/
│       ├── words.json
│       └── strokes.json            # Generated before first start
├── scripts/
│   ├── setup.mjs                   # Create compatible Expo application
│   └── prepare-data.mjs            # Validate words, bundle stroke data
├── tests/core.test.ts
├── licenses/                       # Generated data licenses
├── package.json                    # Generated by official template
├── package-lock.json               # Generated and committed
├── app.json                        # Generated app configuration
├── tsconfig.json                   # Generated TypeScript configuration
├── .gitignore
├── LICENSE
└── THIRD_PARTY_NOTICES.md
```

## 2. Запуск для новичка

Установите Node.js LTS с npm и совместимую Expo Go на телефон.
Распакуйте комплект, откройте терминал в этой папке:

```sh
node scripts/setup.mjs ../hanzi-cards-app
cd ../hanzi-cards-app
npm run typecheck
npm test
npx expo-doctor
npx expo start
```

Путь назначения должен отсутствовать. Для простоты используйте путь без пробелов
и специальных символов. Первый запуск скрипта требует интернет для установки
зависимостей и загрузки данных. Само приложение данные из сети не запрашивает.
Отсканируйте QR-код. Телефон и компьютер должны быть в одной сети; при проблемах
используйте `npx expo start --tunnel`.

Для эмуляторов: `npm run android`; для iOS Simulator на macOS с Xcode:
`npm run ios`. Windows не запускает iOS Simulator. Если установленная Expo Go
не поддерживает SDK сгенерированного проекта, используйте development build
под этот SDK. Веб-версия в данном комплекте не настраивается.

После установки проекта в дальнейшем:

```sh
npm ci
npm run prepare:data
npm run typecheck
npm test
npx expo start
```

## 3. SQLite и структура данных

Полный SQL и инициализация находятся в `src/db.ts`, константа `SCHEMA`.
Таблицы: levels, words, progress, reviews. Включены foreign_keys и WAL;
индексы ускоряют выборку срока повторения и фильтрацию слов.
Слова имеют стабильные ID, BCP-47 коды языков, чтение, перевод, тему и уровень.
Оценка обновляет progress и добавляет reviews в одной эксклюзивной транзакции.
Повторный seed не сбрасывает прогресс. Проверка версии защищает от открытия
новой базы старой программой. Для версии 2 добавляйте последовательную миграцию
внутри транзакции, затем меняйте user_version.

Сейчас word и карточка — одна сущность с одной парой языков. Чтобы добавить
японский, можно добавить записи с ja-JP, чтением kana и en-US переводом;
для отдельной системы уровней добавьте строки levels с собственными ID.
Встроенный импорт пока валидирует именно HSK 1–9. Для нескольких направлений
одного слова следующим шагом выделите lexemes, translations и cards, а progress
привяжите к cardId. Для нескольких пользователей добавьте profileId в ключ
progress. Модуль проверки письма сейчас работает только с Hanzi.

## 4. Интервальные повторения

Good: 1 день, затем 6 дней, затем предыдущий интервал × ease.
Easy увеличивает интервал на 30%, первый интервал минимум 4 дня.
Hard использует предыдущий интервал × 1.2, минимум день.
Again обнуляет серию успешных повторений и возвращает карточку через минуту.
Ease корректируется формулой SM-2, нижняя граница 1.3.

Это адаптация SM-2 с четырьмя оценками, не точное воспроизведение планировщика
Anki. Интервалы — длительности в миллисекундах от оценки, без локальной границы
учебного дня. В UI виден следующий интервал. Ответ нужно открыть перед оценкой.
Просроченные повторения показываются раньше новых карточек. Очередь обновляется
раз в 30 секунд и при возвращении в приложение. Лимита новых карточек пока нет.

## 5. Озвучка и офлайн

`src/speech.ts` использует expo-speech: китайский при открытии карточки,
кнопки Chinese и English для повторного воспроизведения. Перед новой озвучкой
предыдущая останавливается. Отсутствие голоса и ошибка синтеза видны в карточке.

Системный движок не требует собственного аудиобанка или API-ключа.
Но список голосов expo-speech не гарантирует, что каждый голос офлайн:
на Android установите китайский пакет в настройках Text-to-speech и отключите
сетевой синтез в выбранном движке, если такой переключатель есть. На iOS
загрузите китайский голос в настройках доступности/озвучивания.
Проверьте оба языка в авиарежиме. На физическом iPhone выключите silent mode.
Качество и доступность голосов зависят от устройства.

Кэширования аудиофайлов здесь нет: выбран разрешенный заданием вариант
системного TTS. expo-speech не экспортирует звук в файл. Для одинакового голоса
на всех устройствах нужен отдельный сервис с правами на распространение аудио,
серверным ключом, постоянным файловым кэшем и политикой удаления файлов.
Не используйте неофициальные Google Translate TTS endpoints как бесплатный API.

## 6. Письмо и анимация

`WritingCanvas.tsx` рисует SVG-контуры Make Me a Hanzi как светлую подсказку.
PanResponder собирает касания, переводит их из координат 300×300 в координаты
датасета 1024 с инверсией оси Y и базовой линией 900.

Проверка `matchesStroke` ресэмплирует обе траектории в 32 точки по длине дуги.
Проверяются начало/конец (допуск 150), отношение длины (0.5–1.8) и среднее
расстояние соответствующих точек (<100). Сравнение только с текущей ожидаемой
чертой задает порядок; соответствие точек по времени задает направление.
Принятая черта закрашивается зеленым, неверная стирается с подсказкой.
Animate stroke order последовательно показывает движение вдоль медиан и затем
возвращает пользователя к практике. Для многосимвольного слова можно выбрать
каждый иероглиф отдельной кнопкой.

Это базовый учебный валидатор, не распознавание произвольной каллиграфии.
Сходные близко расположенные черты могут быть неоднозначны при таком допуске.
Следующий этап: DTW, проверки изгибов и адаптивные допуски по длине черты.
Результат письма не меняет SRS: оценку памяти пользователь выставляет отдельно.

## 7. Тысячи слов, HSK 1–6+

Замените `src/data/words.json` массивом того же формата из источника с правом
перераспространения. Пример одной записи полностью:

```json
{
  "id": "zh-en-xuexi",
  "text": "学习",
  "reading": "xuéxí",
  "translation": "to study",
  "level": 1,
  "topic": "Education",
  "sourceLanguage": "zh-CN",
  "targetLanguage": "en-US"
}
```

Сохраните стабильные ID. Pinyin уже должен содержать тоны Unicode.
Укажите в метаданных собственного набора версию классификации HSK:
списки HSK 2.0 и HSK 3.0 не взаимозаменяемы. Темы задаются полем topic.
Запустите `npm run prepare:data`, затем перезапустите Metro.
Скрипт валидирует записи, извлекает только нужные иероглифы из
hanzi-writer-data и создает локальный strokes.json. Пропуски выводятся в консоль,
в интерфейсе для них показано сообщение вместо аварийного завершения.

SQLite поддерживает тысячи записей; большой JSON обрабатывается при сборке,
а seed выполняется транзакционно при запуске. Для десятков тысяч слов
замените повторный seed пакетным импортом с версией набора или поставляйте
подготовленную SQLite-базу. Удаление слова из JSON сейчас не удаляет его из БД:
для изъятия записей нужна отдельная миграция/поле active.

Исходный набор содержит 6 слов. Полный словарь HelloChinese сюда не включен.
Бесплатная доступность словаря не равна разрешению на копирование.
Данные контуров лицензированы отдельно: см. THIRD_PARTY_NOTICES.md и licenses/.

## 8. План разработки до публичного релиза

1. Основа: согласовать версию HSK и лицензированный словарь, запустить этот MVP
   на двух физических устройствах, зафиксировать зависимости.
2. Учебная логика: добавить дневной лимит новых карточек, настройки интервалов,
   приостановку карточек, статистику и экспорт/восстановление прогресса.
3. Контент: импортировать полный набор, проверить перевод и тоны,
   маркировать омографы и значения, проверить покрытие данных письма.
4. Письмо: откалибровать допуски на пользователях, сохранять попытки,
   добавить подсказки отдельных черт и тестирование стилуса.
5. Качество: экран настройки офлайн-голосов, VoiceOver/TalkBack,
   масштабирование текста, темная тема, обработка нехватки места.
6. Релиз: приложение с собственными bundle ID/package ID, иконкой,
   политикой конфиденциальности, development/production сборками через EAS,
   проверкой SQLite-миграций и тестированием на TestFlight/Google Play testing.
7. После релиза: опциональная синхронизация, профили, дополнительные языки,
   сравнение планировщика с FSRS. Синхронизация потребует правил конфликтов
   review-log и серверной авторизации; их нет в этом локальном MVP.

## 9. GitHub

После генерации работайте в hanzi-cards-app. Создайте пустой репозиторий GitHub.
Затем выполните (замените YOUR_NAME своим именем):

```sh
git init
git add .
git commit -m "Add offline Hanzi flashcards and handwriting practice"
git branch -M main
git remote add origin https://github.com/YOUR_NAME/hanzi-cards.git
git push -u origin main
```

Если create-expo-app уже создал Git-репозиторий, git init безопасно
переинициализирует его. Если origin уже существует, используйте
`git remote set-url origin ...`. Коммитьте generated strokes.json, licenses/,
package.json и lockfile. node_modules, .expo и личные базы исключены.
Публикацию из этого чата не выполняли.

## 10. Проверки

Автотесты покрывают расписание, переобучение, нижнюю границу ease,
направление черты, правильную траекторию и отклонение каракулей.
Типы и нативные зависимости проверяются после генерации приложения.

Ручной приемочный сценарий: открыть карточку → услышать Chinese → Show answer →
услышать English → Again → дождаться возврата → Good → перезапустить приложение
и убедиться, что карточка не появляется до срока. В письме проверить прямую и
обратную черту, неверный порядок, Clear, Animate и каждый знак в 学习.
Проверить авиарежим в установленной сборке, а не только подключенной к Metro.
